# SG Typer Studio — Windows desktop

SG Typer Studio is a Windows Electron application for manga and comics typesetting. The renderer in
`../web/` is **embedded in the application**; it is not a public website. There is no PWA, Service
Worker, hosted interface manifest, or remote UI download. Windows application updates use
checksummed release metadata and installers published to GitHub Releases.

## Run and verify

On Windows, double-click `start-sg.bat` in the `SG Typer Studio` folder for a small launch/test/build
menu. Press Enter to start the app. The launcher installs missing Electron dependencies before a
source run or installer build, while quick tests need only Node.js. If npm installs the Electron
package without its binary (for example, because lifecycle scripts were skipped), the launcher runs
Electron's own `install.js` directly and reports any download error. The same modes are available
without the menu:

```bat
start-sg.bat start
start-sg.bat test       rem fast offline unit and resource checks
start-sg.bat test-full  rem real Electron E2E
start-sg.bat build      rem Windows x64 NSIS .exe in desktop/dist
```

The equivalent npm commands in `desktop/` are:

```sh
npm install
npm start                 # build embedded content and launch Electron
npm test                  # build content and run the real-app E2E checks
npm run test:unit
```

`npm start`, `npm test`, and `npm run content` copy the renderer and required assets into `content/`.
Git decides what is copied, so ignored commercial lettering fonts stay outside the application.
`desktop/src/main.js` serves only this local `content/` tree through the application origin.

## Windows installer

```sh
npm run dist:win          # x64 NSIS installer in dist/
```

The package contains only Windows targets. It registers PSD/PSB as additional “Open with” choices,
without replacing Photoshop as the default. The installer also registers `sg-typer-studio://` and
the legacy `typer-studio://` link used by the existing TypeR for Photoshop plugin.

Without a signing certificate, Windows SmartScreen may warn during installation. User data is not
removed on uninstall.

## GitHub Releases updates

The installed Windows app has **Help → Check for Updates…**. It checks the GitHub provider from
`build.publish`, shows the release notes, downloads only after
confirmation, reports progress, and offers **Restart and Install** after the installer is verified.
There is no background download or automatic restart. Source runs report that updates require a
packaged application.

For a fully hosted build, open **Actions → Windows release**, enter the new version, and run the
workflow. It configures the current `GITHUB_REPOSITORY`, builds all updater assets on Windows,
publishes the release, and sends Discord only after the installer is attached. No local setup command
is needed.

To move updates and What's New to another repository during a local build, run the following command
in `desktop/`:

```sh
npm run configure:github -- https://github.com/OWNER/REPOSITORY
```

The releases link exposed to the renderer comes from the same `build.publish` configuration. The
Discord announcement workflow automatically uses its current repository and needs only its own
`DISCORD_WEBHOOK_URL` Actions secret. See `docs/new-repository.md` for the complete migration steps.

Every release used by the updater must contain all of these assets:

- `SG Typer Studio-Setup.exe`;
- `SG Typer Studio-Setup.exe.blockmap` when generated;
- `latest.yml` generated by electron-builder.

Build them with `npm run dist:win` after incrementing `desktop/package.json` and the lockfile to a
new semantic version. Upload the generated files to the same published GitHub Release. Do not rename
`latest.yml` or replace the installer without also replacing its metadata. The `latest.yml` SHA-512
and size checks protect the download; an Authenticode certificate is still recommended for Windows
SmartScreen and publisher verification.

To publish directly from electron-builder, use a locally configured `GH_TOKEN` with permission to
create releases and run `electron-builder --win --x64 --publish always`. Never commit that token.
Manual release upload works without a token in the project.

## Existing TypeR Studio profiles

On first launch, if `%APPDATA%/SG Typer Studio` does not exist yet, the application copies the legacy
`%APPDATA%/TypeR Studio` profile. The old profile remains untouched as a rollback. Caches and remotely
downloaded interface content are excluded. IndexedDB, local storage, open documents, recent files,
fonts, and settings therefore remain available under the new product name.

Internal `TypeR*` JavaScript names, the application origin, storage keys, the Photoshop exchange
folder, and the legacy link scheme are compatibility identifiers. They do not load a website and
should not be renamed without a corresponding data/plugin migration.

## Native functionality kept in Electron

- File System Access handles and native Windows file associations.
- Windows per-user font installation and Font FindeR support.
- Photoshop discovery, document exchange, and Open in Photoshop.
- Adobe Firefly in an isolated session owned by the main process.
- Optional local FLUX models; model files are downloaded only after explicit user consent.
- Local INDD → IDML conversion through the bundled WASM module.
- Discord Rich Presence through the local Discord IPC socket, with no website button or remote icon.
  Set `SG_DISCORD_ID` to use a Discord application registered with the new brand.

## Adobe Firefly validation

```sh
node --test scripts/test-firefly.js scripts/test-firefly-credits.js
npm run content
node scripts/test-firefly-e2e.js --login
```

Generation tests use a simulated transport. `--login` checks the real Adobe login window and
cancellation, but does not prove that an account has generation rights or that a generation succeeds.

For installed-app Windows checks:

```sh
node scripts/test-windows.js "<path to SG Typer Studio.exe>"
```
